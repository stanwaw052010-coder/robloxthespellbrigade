# Magic Brigade (Магический Отряд)

Кооперативный wave-defense шутер про отряд волшебников в стиле **The Spell
Brigade**, реализованный на Roblox / Luau. 1–8 игроков защищают портал от волн
монстров, используя заклинания из разных книг (классов).

> A co-op wave-defense spell shooter for Roblox. A party of wizards defends a
> portal against escalating monster waves using elemental spellbooks. Fully
> server-authoritative combat, a procedural arena and HUD, and no imported
> assets required — it runs the moment you sync it into Studio.

---

## Быстрый старт (Quick start)

Проект использует [Rojo](https://rojo.space) для синхронизации кода с Roblox
Studio.

```bash
# 1. Установите инструменты (Rojo и др.)
rokit install          # или: aftman install

# 2. Запустите сервер синхронизации
rojo serve             # затем подключитесь плагином Rojo в Studio

# --- либо соберите готовый .rbxl ---
rojo build -o MagicBrigade.rbxl
```

После подключения нажмите **Play** в Studio. Арена, HUD и волны создаются
автоматически. Управление:

| Действие | ПК | Мобильные |
|---|---|---|
| Базовая атака | ЛКМ (удерживать) | кнопка 🔥 |
| Заклинание Q | `Q` | кнопка Q |
| Заклинание E | `E` | кнопка E |
| Ультимейт | `R` | кнопка R |
| Лобби (книги / внешность / отряд) | кнопка «📖 Лобби» | кнопка «📖 Лобби» |

Прицеливание — по курсору/касанию; на мобильных есть авто-наведение на
ближайшего врага.

### Ключевой принцип: сервер — авторитет

Клиент **только** отправляет запрос «хочу скастовать заклинание X с прицелом в
точку P». Сервер (`SpellCastingService`) проверяет всё сам:

1. rate-limit (`AntiExploit`) — защита от спама ремоутов;
2. заклинание существует и есть в экипированной книге игрока;
3. кулдаун прошёл (серверный таймер, с учётом апгрейдов);
4. хватает маны (мана считается и регенерируется на сервере);
5. точка прицела в пределах дальности (+ допуск на задержку сети).

Только после этого урон/эффекты применяются через `DamageService`. Клиенту
никогда не доверяются урон, кулдауны, мана и цели — он отвечает лишь за ввод,
предсказание кулдаунов для отзывчивости UI и визуальные эффекты.

## Игровой цикл

1. Игрок заходит → выбирает книгу заклинаний (панель «📖 Книги»).
2. Матч стартует автоматически (grace-таймер), затем идут волны.
3. Каждая волна сложнее (больше HP/урона/врагов); каждая 5-я — мини-босс,
   каждая 10-я — босс (`GameConfig.Wave`).
4. Между волнами — окно 20 сек: магазин апгрейдов (за голд).
5. Голд — за убийства и зачистку волн; опыт — за убийства (уровни игрока);
   эссенция — по итогам матча (мета-валюта для разблокировки книг в лобби).
6. База уничтожена → экран итогов (волны, урон, лечение, убийства), затем
   новый матч.

Прогресс (эссенция, уровень, разблокированные книги, статистика) сохраняется
через `PlayerDataService` (DataStore с автосейвом; в Studio без доступа к API
работает в сессионном режиме).

## Книги заклинаний (классы)

| Книга | Роль | Особенности |
|---|---|---|
| 🔥 Огонь | AoE / DoT | урон по площади, поджиг (Burn) |
| ❄️ Лёд | Контроль | заморозка, замедление |
| 🪨 Земля | Танк / контроль | каменные стены-препятствия, землетрясение, щит отряду |
| ⚡ Молния | Бёрст / крит | цепной урон, высокий крит |
| ✨ Исцеление | Саппорт | лечение и щиты союзникам |
| 💀 Некромантия | Призыв / дебафф | миньоны-скелеты, ослабление врагов |

Каждая книга: базовая атака + 2 активных скилла (Q/E) + ультимейт.
Определяются данными в `src/Shared/SpellbookModule.luau`.

## Апгрейды: общие + дерево по каждому заклинанию

Магазин между волнами имеет две вкладки-слоя (`src/Shared/UpgradeCatalogue.luau`):

1. **Общие** — множители на всю книгу: урон, кулдаун, радиус, стоимость маны.
2. **По заклинанию** — у каждого заклинания своё дерево: `Мощь` (+урон),
   `Скорость` (−кулдаун), `Радиус` (+зона), а у части заклинаний — ещё и
   **сигнатурный узел**, меняющий саму механику:

| Заклинание | Сигнатура | Эффект |
|---|---|---|
| Fireball | ⭐ Двойной взрыв | взрывается ещё раз через 0.6 с (60% урона) |
| Meteor Storm | ⭐ Катаклизм | бьёт трижды с задержкой |
| Frost Nova | ⭐ Раскол | +60% урона по уже замороженным |
| Chain Lightning | ⭐ Перегрузка | +3 перескока и меньшее затухание |
| Stone Wall | ⭐ Великая стена | три стены в ряд, держатся вдвое дольше |
| Mend | ⭐ Перелив | избыточное лечение становится щитом |
| Raise Skeleton | ⭐ Легион | +2 призванных скелета |

Всё покупается за голд и валидируется на сервере (`UpgradeService`): нельзя
купить узел для заклинания из чужой книги, превысить максимальный уровень или
потратить золото, которого нет. Клиенту передаются только **уровни** — сколько
стоит каждый уровень и что он даёт, решает сервер.

## Отряд и матчмейкинг

- **Табло отряда** (`PartyService` → `PartyFrameController`): HP/мана/класс
  каждого союзника, сервер рассылает снапшот 5 раз в секунду. Клиент не читает
  чужие `Humanoid` напрямую.
- **Миникарта** (`MinimapController`): портал, союзники, враги, боссы и
  призванные миньоны; круглый радар, обновление 12 Гц с пулом «блипов».
- **Матчмейкинг** (`MatchmakingService`): сбор отряда в лобби и — при
  `GameConfig.Matchmaking.Enabled = true` — телепорт всей группы в
  зарезервированный сервер через `TeleportService:ReserveServer`.
  По умолчанию **выключен**: все играют в одном инстансе, что и нужно в Studio
  (там резервирование недоступно). Любая ошибка телепорта не оставляет отряд в
  подвешенном состоянии — матч просто начинается на текущем сервере.

## Кастомизация персонажа (§6.1)

`CosmeticsService` собирает всю внешность из примитивов и приваривает к аватару,
не перекрашивая его собственные части:

- **Роба и мантия** — цвет по стихии выбранной книги (класс читается издалека)
- **Книга заклинаний** в руке — «hero prop» со свечением по стихии
- **Головные уборы** — капюшон, шляпа мага, обруч, корона (за эссенцию)
- **Ауры** — партиклы: угли, иней, гроза, цветение, сияние, пустота

Покупка и надевание валидируются на сервере, выбор сохраняется в профиле.

## Уникальные враги и боссы (раздел 4.1)

У каждого врага — своя механика, а не просто HP:

| Враг | Механика |
|---|---|
| Гоблин | базовый ближний бой |
| Скелет-лучник | стреляет издалека |
| Ядовитый слизень | при смерти оставляет лужу яда (DoT-зона на полу) |
| Взрывной гоблин | взрывается при смерти/контакте с базой (AoE) |
| Морозный волк | при ударе накладывает замедление на игрока |
| Тень | периодически неуязвима и телепортируется (окна уязвимости) |
| Щитоносец | щит спереди — бить нужно со спины |

**Боссы** (3 фазы по % HP, с телеграфами атак — красная зона на полу за ~1.3 сек):
- **Огненный Голем** (волна 5): огненные волны → призыв элементалей (фаза 2) → берсерк с огненной аурой (фаза 3)
- **Лич** (волна 10): призыв скелетов и тьма → зоны запрета каста (нельзя колдовать внутри) → воскрешение теневых копий

Технически: `EnemyEffectsModule` (каталог эффектов), `DamageService` (применение Burn/Poison/Freeze/Stun/Invulnerable/щиты), `BossController` (фазы через % HP, способности, телеграфы, зоны).

## Визуальный стиль (раздел 6.1)

- `AmbianceController` — `Lighting.Technology = Future`, Bloom, ColorCorrection, Atmosphere; DepthOfField включён в лобби и выключается в бою
- `VFXController` — партиклы по цвету стихии, вспышки/кольца/лучи, **тряска камеры** на тяжёлых попаданиях рядом с игроком
- HUD — рамки иконок скиллов по цвету стихии, вспышка полосы HP при получении урона

## Заметки по контенту и оптимизации

- **Ассеты-заглушки.** Враги, арена, портал и VFX строятся процедурно из
  примитивов, поэтому внешние `.rbxm`/анимации/звуки не требуются. Поля
  `Animation`/`SoundId`/`VFX` в данных заклинаний — плейсхолдеры
  (`rbxassetid://0`); подставьте реальные загруженные ассеты.
- **Оптимизация.** VFX уничтожаются через `Debris`; враги удаляются с
  задержкой; статус-эффекты тикаются одним циклом `Heartbeat`. Для тяжёлых
  нагрузок замените процедурные снаряды на пул объектов (object pooling).
- **DataStore.** Для продакшена рекомендуется заменить `PlayerDataService`
  на ProfileService/DataStore2 (session-locking).
- **Матчмейкинг.** `MatchmakingService` умеет резервировать сервер под отряд,
  но по умолчанию выключен (`GameConfig.Matchmaking.Enabled = false`), так как
  `ReserveServer` требует опубликованного места и не работает в Studio.
- **Проверка кода.** Проект собирается и проходит анализ пиннутыми
  инструментами: `rojo build default.project.json -o MagicBrigade.rbxl` и
  `luau-lsp analyze --sourcemap=<sourcemap> --defs=<globalTypes> src/`.

## О референсе (The Spell Brigade)

Промпт просил уточнить детали оригинала. В реальной *The Spell Brigade*
геймплей ближе к **survivors-like** (авто-каст заклинаний, движение по арене,
сбор опыта из выпадающих кристаллов, прокачка между уровнями), только PvE,
монетизация — премиум-покупка. Данный проект реализует **вариант из
технического задания** (wave-defense с ручным кастом и защитой портала).
Чтобы приблизить к оригиналу:

- переключить каст с ручного на авто-таргет ближайших врагов;
- заменить защиту базы на выживание по таймеру + сбор опыта-кристаллов;
- добавить выбор апгрейда из 3 случайных карт при повышении уровня.

Эти изменения локализуются в `SpellCastingService`, `WaveManager` и
`UpgradeService` без переработки архитектуры.
