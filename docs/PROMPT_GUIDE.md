# Как написать промпт для Claude Code, чтобы получить рабочую игру в Roblox

Практическое руководство, выжатое из опыта разработки этого проекта
(`Magic Brigade`: ~6000 строк Luau, Rojo, серверный авторитет, без внешних
ассетов). Внутри — готовый мастер-промпт, который можно копировать и
подставлять свою игру.

---

## 0. Главное, что нужно понять до написания промпта

**Claude Code не может открыть Roblox Studio и нажать Play.** У него нет
GUI, нет Roblox-аккаунта, нет доступа к Toolbox. Значит:

- фраза «сделай без ошибок» сама по себе не работает — это пожелание, а не
  проверка;
- «без ошибок» достигается тем, что в промпте задана **проверяемая среда**
  (Rojo-сборка + статический анализ) и **запрет на всё непроверяемое**
  (в первую очередь — на внешние ассеты);
- честная граница: статика ловит ~90 % проблем (синтаксис, типы, битые
  пути, несуществующие поля модулей). Оставшиеся ~10 % — рантайм-логика,
  баланс, физика — ловятся только запуском в Studio. Поэтому в промпт
  закладывается **цикл**: сборка → Play → текст ошибки обратно в Claude Code.

Промпт должен превратить «сделай игру» в задачу, которую можно **проверить
командой в терминале**.

---

## 1. Пять причин, почему сгенерированная игра не запускается

| # | Причина | Как выглядит в Studio | Лечение в промпте |
|---|---|---|---|
| 1 | **Выдуманные ассеты.** Модель не может загрузить меши/звуки/анимации, поэтому пишет правдоподобные `rbxassetid://123456789` | Невидимые враги, тишина, `Failed to load asset` | Запретить любые внешние id. Всё — из примитивов кодом. Где id обязателен — `rbxassetid://0` + `-- TODO: asset` |
| 2 | **Устаревший/несуществующий API.** `wait()`, `spawn()`, `BodyVelocity`, `Humanoid:LoadAnimation`, `Instance.new("Part", parent)` | Варнинги, деприкейты, «X is not a valid member of Y» | Дать явные белый и чёрный списки API (см. мастер-промпт) |
| 3 | **Код не туда положен.** Нет структуры — непонятно, что серверный скрипт, что клиентский | Скрипт молча не запускается | Задать Rojo + `default.project.json` как обязательную первую фазу |
| 4 | **Нарушена граница клиент/сервер** (FilteringEnabled) | «Работает у меня, не работает у других», урон не проходит | Правило «сервер — авторитет» + валидация каждого RemoteEvent |
| 5 | **Один гигантский one-shot** без промежуточных проверок | 3000 строк, из них 40 не компилируются | Фазы с гейтами: следующая фаза не начинается, пока сборка не зелёная |

## 2. Анатомия рабочего промпта: 8 блоков

| Блок | Зачем | Цена пропуска |
|---|---|---|
| 1. Роль и цель | Задаёт уровень решений | Код «как в туториале» |
| 2. Геймплейное ТЗ **с цифрами** | Главный источник качества | Модель придумает свою игру |
| 3. Стек и структура | Куда класть код | Каша из скриптов |
| 4. Жёсткие технические ограничения | Отсекает нерабочие пути | Ассеты-призраки, deprecated API |
| 5. Порядок работы по фазам | Управляет объёмом | Развал на большом объёме |
| 6. Команды проверки | Делает «без ошибок» проверяемым | Нечем измерить результат |
| 7. Критерии приёмки (DoD) | Когда задача закончена | Бесконечная полировка |
| 8. Формат отчёта | Что проверять руками | Непонятно, что реально готово |

Правило: **конкретика вместо прилагательных.** «6 книг заклинаний, у каждой
базовая атака + 2 скилла + ультимейт, все числа в `GameConfig`» работает,
«интересная боевая система» — нет.

## 3. Мастер-промпт (копировать и заполнить `<...>`)

````text
# РОЛЬ
Ты — senior Roblox-разработчик. Твоя задача — законченный, запускаемый
проект игры на Luau + Rojo, который начинает работать сразу после
синхронизации в Studio и нажатия Play. Никаких заготовок «доделаю позже»
в основном игровом цикле.

# ИГРА
Жанр / референс: <например: кооп wave-defense в духе The Spell Brigade>
Игроков: <1–8, PvE>
Длительность сессии: <5–15 минут>
Платформы: ПК + мобильные (тач-управление обязательно)

# ГЕЙМПЛЕЙНОЕ ТЗ (соблюдать буквально, цифры не менять)
- Основной цикл: <спавн волн → бой → магазин между волнами → следующая волна>
- Условие победы/поражения: <база уничтожена = поражение>
- Прогрессия в матче: <голд за убийства → апгрейды между волнами>
- Мета-прогрессия: <эссенция → разблокировка классов, сохраняется>
- Контент первой версии — ровно столько:
  * <6> классов/наборов способностей, у каждого: <базовая атака + 2 скилла + ульта>
  * <7> типов врагов, у каждого своя механика (не только разное HP)
  * <2> босса с фазами и телеграфами атак
  * <10> волн + генератор бесконечных волн после
- Все числа баланса (урон, кулдауны, HP, цены) — в ОДНОМ модуле конфига.

# СТЕК И СТРУКТУРА (обязательно)
- Luau, `--!strict`, `.luaurc` с languageMode = strict
- Rojo 7 (`default.project.json`), тулчейн через `rokit.toml`
  (rojo, stylua, luau-lsp)
- Структура:
  src/Shared/   → ReplicatedStorage.Shared (данные, конфиги, Remotes, утилиты)
  src/Server/   → ServerScriptService (init.server.luau + Services/)
  src/Client/   → StarterPlayerScripts (init.client.luau + контроллеры)
- Сервисы/контроллеры с методами Init() и Start(); бутстрап вызывает сначала
  все Init(), затем все Start()
- Данные отдельно от логики: каталоги врагов/способностей/волн — чистые
  таблицы, без побочных эффектов
- Один модуль — одна ответственность, потолок ~600 строк на файл
- Публичные функции — с аннотациями типов

# ЖЁСТКИЕ ОГРАНИЧЕНИЯ
1. НИКАКИХ внешних ассетов. Запрещено выдумывать `rbxassetid://<число>`.
   Враги, арена, снаряды, VFX, UI — процедурно из Part / ParticleEmitter /
   Beam / Trail / кода UI. Если поле API требует id — ставь
   `rbxassetid://0` и рядом комментарий `-- TODO: подставить свой ассет`.
   Игра обязана быть визуально читаемой без единого загруженного ассета.
2. Сервер — единственный авторитет. Клиент отправляет только НАМЕРЕНИЕ
   («хочу применить способность X в точку P»). Сервер сам проверяет:
   rate-limit, существование способности у игрока, кулдаун, ресурс (мана),
   дистанцию до цели с допуском на пинг. Урон, HP, валюта, дроп — только на
   сервере. Клиенту нельзя доверять ничего, кроме ввода.
3. Только современный API:
   task.wait / task.spawn / task.delay / task.defer, Instance.new("X") с
   последующим присваиванием Parent, TweenService, LinearVelocity /
   AlignPosition / AlignOrientation, Humanoid.Animator:LoadAnimation,
   UserInputService / ContextActionService, Debris или task.delay для
   очистки, CollectionService для тегов.
   ЗАПРЕЩЕНО: wait(), spawn(), delay(), Instance.new("Part", parent),
   :remove(), BodyVelocity / BodyPosition / BodyGyro, Humanoid:LoadAnimation,
   LoadLibrary, `while true do wait() end` без разрыва, глобальные переменные.
4. Каждое :Connect() имеет владельца и явную отписку при удалении объекта,
   выходе игрока или конце матча. Никаких вечно висящих соединений.
5. Никаких «Infinite yield possible»: WaitForChild на сервере — только с
   таймаутом и обработкой nil.
6. DataStore — только внутри pcall с ретраями и экспоненциальной задержкой.
   В Studio без доступа к DataStore проект обязан работать (fallback в
   сессионную память, без ошибок в Output).
7. Код не имеет права полагаться на объекты, которых нет в
   `default.project.json`. Арена, спавны, точки интереса создаются кодом
   при старте. Игрок обязан появляться на твёрдой поверхности — проверить,
   что SpawnLocation существует и находится над полом.
8. Мобильные: экранные кнопки для всех действий, никакого управления
   «только клавиатура».

# ПОРЯДОК РАБОТЫ (не нарушать)
Фаза 0. Скелет: rokit.toml, default.project.json, .luaurc, .gitignore,
        пустые точки входа. ГЕЙТ: `rojo build -o build.rbxl` проходит.
Фаза 1. Shared: конфиг баланса, каталоги данных, реестр Remotes, утилиты.
        ГЕЙТ: сборка + анализ чистые.
Фаза 2. Сервер: минимально играбельный цикл (спавн врага → урон → смерть →
        волна → поражение). ГЕЙТ: сборка + анализ чистые.
Фаза 3. Клиент: ввод, HUD, отображение состояния. ГЕЙТ: тот же.
Фаза 4. Контент и полировка: остальные классы/враги/боссы, VFX, сохранения,
        экран итогов. ГЕЙТ: тот же.
После КАЖДОЙ фазы: прогнать проверки, починить всё найденное, сделать
отдельный коммит с внятным сообщением. Не начинать следующую фазу с
красной сборкой.

# ПРОВЕРКИ (запускать самому, не перекладывать на меня)
rojo build -o build.rbxl                       # структура и синтаксис
stylua --check src                             # форматирование
rojo sourcemap default.project.json -o sourcemap.json
luau-lsp analyze --sourcemap=sourcemap.json \
  --defs=globalTypes.d.luau --base-luaurc=.luaurc src   # типы, 0 ошибок
grep -rnE "\b(wait|spawn|delay)\(|BodyVelocity|BodyPosition|:remove\(" src
  # должно быть пусто
grep -rn "rbxassetid://[1-9]" src              # должно быть пусто

# КРИТЕРИИ ПРИЁМКИ
- Все команды выше проходят; варнинги, которые остались, — объяснены.
- В основном игровом цикле нет TODO и заглушек.
- У каждого RemoteEvent есть серверная валидация входных данных.
- Игра запускается на пустом Baseplate и играбельна одним игроком.
- README на русском: установка тулчейна, `rojo serve`, подключение плагина,
  управление, архитектура.

# ЧЕГО НЕ ДЕЛАТЬ
- Не выдумывать свойства и методы Roblox API. Сомневаешься — проверь
  документацию или выбери заведомо существующий путь.
- Не подменять моё ТЗ своим «улучшенным».
- Не молчать о нереализованном: если что-то не сделано — скажи прямо.
- Не менять правила из этого промпта без согласования.

# ОТЧЁТ В КОНЦЕ
1. Список созданных файлов с одной строкой описания.
2. Что реализовано полностью / частично / не реализовано и почему.
3. Результаты всех команд проверки.
4. Что мне нужно проверить руками в Studio (конкретный список действий).
5. Известные ограничения и следующий логичный шаг.
````

Файл `globalTypes.d.luau` для анализатора берётся один раз:

```bash
curl -sL -o globalTypes.d.luau \
  https://raw.githubusercontent.com/JohnnyMorganz/luau-lsp/main/scripts/globalTypes.d.luau
```

## 4. Мини-промпты для итераций

Мастер-промпт — для старта. Дальше 90 % работы — короткие точные запросы.

**Ошибка из Output Studio** (самый ценный тип запроса — у Claude Code нет
Studio, поэтому текст ошибки от вас стоит дороже любых описаний):

```text
Ошибка в Studio при <что делал: нажал Play / скастовал Q / волна 3>:

<полный текст ошибки + стек вызовов, целиком, не пересказом>

Найди корневую причину, покажи её, почини минимальным изменением.
Архитектуру не переписывай. Объясни, почему это произошло, и проверь,
нет ли той же ошибки в других местах. После правки прогони rojo build и
luau-lsp analyze.
```

**Новая фича:**

```text
Добавь <фича> по правилам проекта из CLAUDE.md.
Ограничения: не трогать <модули>, все числа — в GameConfig, серверная
валидация обязательна. Сначала покажи план из 3–5 пунктов, потом делай.
После — прогони проверки и скажи, что тестировать в Studio.
```

**Баланс без риска сломать код:**

```text
Правь только GameConfig и таблицы данных, код логики не трогай.
Цель: <волна 5 слишком сложная для одного игрока>. Покажи диффом старые
и новые значения с обоснованием.
```

**Ревью перед запуском:**

```text
Проверь код на типовые ошибки Roblox: утечки соединений, отсутствие
отписок при выходе игрока, доверие клиенту в RemoteEvent, deprecated API,
WaitForChild без таймаута, гонки при старте сервисов. Отчёт списком:
файл:строка → проблема → как чинить. Ничего не меняй, пока не одобрю.
```

## 5. Рабочий цикл

```
Промпт → Claude Code пишет и статически проверяет
      → rojo serve / rojo build
      → вы жмёте Play в Studio
      → копируете ВЕСЬ текст ошибки из Output
      → мини-промпт «Ошибка из Output»
      → повтор, пока Output не чист
```

Что даёт наибольший прирост «безошибочности» на практике:

1. Отдавать ошибку **полностью, со стеком** — не «не работает магазин».
2. Одна проблема — один запрос. Пять ошибок сразу → размытые правки.
3. После каждой зелёной итерации — коммит. Есть куда откатиться.
4. Просить не только фикс, но и **причину** — повторные ошибки того же
   класса исчезают.
5. Держать сессию сфокусированной: смена темы каждые два сообщения ломает
   контекст сильнее, чем длинный код.

## 6. CLAUDE.md — чтобы не повторять правила каждый раз

Правила из блока «Жёсткие ограничения» не нужно копировать в каждый промпт.
Claude Code автоматически читает `CLAUDE.md` из корня репозитория в начале
сессии. В этом проекте он уже лежит рядом с этим файлом. Тогда промпты
сжимаются до сути:

> Добавь врага «Каменный страж» по правилам проекта.

Полезно также иметь `.claude/settings.json` с разрешениями на частые
команды (`rojo build`, `stylua`, `luau-lsp`), чтобы сессия не спотыкалась о
подтверждения.

## 7. Чек-лист приёмки в Studio (проверять руками)

- [ ] `rojo serve` → плагин подключается, дерево появилось без красных узлов
- [ ] Play: Output пуст (ни одной красной строки, деприкейты — тоже сигнал)
- [ ] Персонаж появляется на полу и не падает в пустоту
- [ ] Основное действие работает с первой секунды (атака/движение/каст)
- [ ] HUD виден и не наезжает на элементы Roblox-меню
- [ ] Test → 2 Players: урон и состояние совпадают у обоих клиентов
- [ ] Мобильная эмуляция: все действия доступны кнопками
- [ ] Конец матча → экран итогов → новый матч без ошибок
- [ ] Перезаход игрока: прогресс на месте, соединения не утекли
- [ ] Micro Profiler / Script Performance: нет скрипта, съедающего кадр

## 8. Антипаттерны в самих промптах

| Формулировка | Что произойдёт |
|---|---|
| «Сделай крутую игру как <хит>» | Модель напишет ТЗ за вас — почти наверняка не то |
| «Без ошибок и багов» без команд проверки | Пожелание, которое нечем измерить |
| «Возьми бесплатные модели из Toolbox» | Недоступно; получите выдуманные id |
| «Сделай всё сразу, быстро» | Объём без гейтов = красная сборка в конце |
| «Залей игру в Roblox» | Нет доступа к аккаунту; публикация — только руками |
| «Почини всё, что найдёшь» после длинного списка | Правки без приоритета, риск задеть рабочее |
| Ошибка пересказом («ломается магазин») | Диагностика вслепую, несколько лишних итераций |

## 9. Как это выглядело на этом проекте

Промпт для `Magic Brigade` содержал: жанр и референс, точный список
контента (6 книг, 7 врагов, 2 босса с фазами и телеграфами), требование
серверного авторитета, запрет внешних ассетов и структуру Rojo. Результат —
25 модулей, ~6000 строк, играбельно сразу после `rojo serve` + Play.

Что всё равно потребовало отдельных итераций (и что статика поймать не
могла):

- игроки падали в пустоту на Play — арена создавалась позже спавна
  (коммит `Fix players spawning into the void`);
- боссы и уникальные механики врагов добавлялись второй фазой, а не в
  первом заходе.

Вывод: одноразовый промпт даёт скелет и 80 % контента. Оставшееся —
короткие итерации по ошибкам из Output. Именно поэтому в мастер-промпте
есть блок «Отчёт»: он говорит, что идти проверять руками.
